// PRIORITY ISSUES
P0

Arabic text rendered in Segoe UI

ArabicFontFamily = "Segoe UI" in App.xaml. Segoe UI is a Latin-first system font that cannot correctly join Arabic letters, position diacritics, or maintain Quranic textural quality. The entire verse panel (28px Arabic), transcription panel (20px Arabic), and progress list depend on this. The app's core value proposition is Arabic recitation feedback — broken Arabic rendering breaks the product.

FIX: `/design typeset` — Bundle and apply a proper Arabic typeface (Noto Naskh Arabic, Amiri, or Scheherazade New). Set ArabicFontFamily as a distinct resource from UiFontFamily. Add measure control (~45-55ch) for the 28px verse text.
P1

Zero keyboard interaction on a Windows-first desktop app

No keyboard shortcuts, no TabIndex ordering, no visible focus rings. A desktop app targeting Windows 10/11 where the user must use the mouse for everything — including toggling the mic, resetting the session, and navigating the verse selector. The login page has no Enter-to-submit. Picker controls disabled during recording show zero visual change.

FIX: `/design interaction` — Add Spacebar to toggle mic, Escape to reset, Tab ordering through verse selector, visible focus rings, disabled-state opacity on pickers, Enter-to-submit on login.
P1

6 bordered panels create flat visual plane

The Recitation page scroll area contains: transcription panel, verse panel, placeholder panel, tajweed violations panel, and ASR debug panel — all as Border elements with RoundRectangle corners and similar visual weight. Only the verse panel uses a 2px stroke; everything else is 1px. There's no z-ordering, no nesting hierarchy, no progressive disclosure. The eye can't distinguish primary content from secondary diagnostics.

FIX: `/design relayout` — Consolidate secondary panels (tajweed, ASR debug) into a collapsible diagnostics section below the verse. Reduce the transcription panel's visual weight (lighter border, smaller heading). The verse panel + confidence bar should dominate.
P2

30+ hardcoded hex values, cool/warm temperature clash

Only 6 colors are tokenized in App.xaml; ~30 more appear as inline hex. Transcription panel uses cool Tailwind grays (#F9FAFB, #D1D5DB, #374151) against a warm cream surface (#F9F6EF). The Gold (#C9A84C) token is declared but referenced zero times. No dark mode infrastructure exists. The app feels like two palettes stitched together.

FIX: `/design recolor` — Tokenize all hex values as named Color resources. Shift cool grays to warm-tinted equivalents (e.g., #FAF8F4 instead of #F9FAFB). Actually use the Gold token for accent moments. Add AppThemeBinding scaffolding for dark mode.
P2

Emoji logo reads as placeholder identity

The login page header is "🕌 Tarteel" in Segoe UI Bold at 32px. An emoji as a brand mark signals "TODO: add logo" — it's the universal placeholder gesture. There is no other brand surface — no splash, no about page, no app icon reference.

FIX: `/design voice` — Decide register (utility vs companion), then either use clean typographic wordmark or a proper SVG/path logo. Commit to one personality.
